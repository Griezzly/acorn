## Observability Stack (Docker Compose)

This directory contains the Docker Compose configuration for the complete observability stack used in Acorn benchmarking.

### Components

The stack includes three services that communicate via a Docker network:

1. **Loki** (port 3100) - Log aggregation
   - Receives logs from Promtail agents running on worker nodes
   - Stores logs with efficient indexing and compression
   - Queryable via LogQL

2. **Prometheus** (port 9090) - Metrics collection
   - Scrapes metrics from Node Exporter on worker nodes
   - Stores time-series data with 30-day retention
   - Queryable via PromQL

3. **Grafana** (port 3000) - Visualization
   - Pre-configured with Loki and Prometheus datasources
   - Dashboard for logs and metrics
   - Login: admin/admin

### Quick Start

Use the automated setup script:

```bash
cd scripts
./setup-observability.sh
```

This script:
- Generates `prometheus.yml` with all worker targets from Terraform
- Starts all services via Docker Compose
- Verifies connectivity and datasources
- Displays access URLs and example queries

### Files

- **docker-compose.yml** - Service definitions and network configuration
- **prometheus.yml** - Prometheus configuration (auto-generated by setup script)
- **prometheus.yml.template** - Template for Prometheus config
- **grafana-provisioning/** - Grafana datasource auto-provisioning
  - `datasources/datasources.yml` - Loki and Prometheus datasources
- **grafana-dashboard.json** - Pre-built benchmark dashboard

### Manual Setup

If you prefer manual control:

1. **Generate Prometheus configuration:**
   ```bash
   # Copy template
   cp prometheus.yml.template prometheus.yml

   # Add worker targets manually
   vim prometheus.yml
   ```

2. **Start services:**
   ```bash
   docker-compose up -d
   ```

3. **Verify services are running:**
   ```bash
   docker-compose ps
   ```

4. **Access UIs:**
   - Grafana: http://localhost:3000 (admin/admin)
   - Prometheus: http://localhost:9090
   - Loki: http://localhost:3100 (API only)

### Managing Services

```bash
# View all logs
docker-compose logs -f

# View specific service logs
docker-compose logs -f prometheus
docker-compose logs -f loki
docker-compose logs -f grafana

# Restart all services
docker-compose restart

# Restart specific service
docker-compose restart prometheus

# Stop all services (keeps data)
docker-compose down

# Stop and remove all data
docker-compose down -v

# Update and restart
docker-compose pull
docker-compose up -d
```

### Updating Worker Targets

When you add/remove workers:

1. **Re-run setup script:**
   ```bash
   cd ../scripts
   ./setup-observability.sh
   ```

2. **Or update manually:**
   ```bash
   # Edit prometheus.yml and add worker targets
   vim prometheus.yml

   # Reload Prometheus (no restart needed)
   curl -X POST http://localhost:9090/-/reload
   ```

### Grafana Datasources

Datasources are automatically provisioned via `grafana-provisioning/datasources/datasources.yml`:

- **Loki** (default) - Connected to `http://loki:3100`
- **Prometheus** - Connected to `http://prometheus:9090`

No manual configuration needed. Datasources appear automatically when Grafana starts.

### Importing Dashboards

**Option 1: Via Grafana UI**
1. Open http://localhost:3000
2. Click "+" → "Import"
3. Upload `grafana-dashboard.json`
4. Select datasources (Loki/Prometheus)
5. Click "Import"

**Option 2: Via API**
```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -d @acorn-dashboard.json \
  http://admin:admin@localhost:3000/api/dashboards/db
```

### Data Persistence

Data is stored in Docker volumes:
- **prometheus-data** - 30 days of metrics
- **grafana-data** - Dashboards, users, settings

To back up data:
```bash
# List volumes
docker volume ls

# Inspect volume location
docker volume inspect benchmarks_prometheus-data

# Backup (while services are running)
docker run --rm -v benchmarks_prometheus-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/prometheus-backup.tar.gz -C /data .
```

To restore data:
```bash
# Stop services
docker-compose down

# Restore
docker run --rm -v benchmarks_prometheus-data:/data -v $(pwd):/backup \
  alpine tar xzf /backup/prometheus-backup.tar.gz -C /data

# Restart services
docker-compose up -d
```

### Networking

All services run in the `observability` Docker network:
- Services can reference each other by service name (e.g., `http://loki:3100`)
- Grafana datasources use internal DNS names
- External access is via published ports (3000, 3100, 9090)

### Resource Usage

Typical resource consumption:
- **Loki**: ~200MB RAM
- **Prometheus**: ~500MB RAM (depends on scrape targets and retention)
- **Grafana**: ~100MB RAM

Total: ~800MB RAM for the observability stack.

### Troubleshooting

**Services not starting:**
```bash
# Check logs
docker-compose logs

# Check specific service
docker-compose logs loki
docker-compose logs prometheus
docker-compose logs grafana

# Check service health
docker-compose ps
```

**Grafana can't reach Prometheus/Loki:**
- Services are in the same Docker network
- Use service names, not localhost (e.g., `http://prometheus:9090`)
- Check datasource configuration in Grafana UI

**Prometheus not scraping workers:**
- Verify `prometheus.yml` has worker targets
- Check Prometheus targets page: http://localhost:9090/targets
- Ensure workers are accessible via Tailscale: `ping acorn-worker-1`
- Verify Node Exporter is running on workers: `ssh root@worker systemctl status node_exporter`

**Loki not receiving logs:**
- Check Promtail is running on workers: `ssh root@worker systemctl status promtail`
- Verify Loki URL in Promtail config: `ssh root@worker cat /etc/promtail/config.yml`
- Check Loki logs: `docker-compose logs loki`

**Out of disk space:**
```bash
# Check Docker disk usage
docker system df

# Clean up old images and containers
docker system prune

# Reduce Prometheus retention (edit docker-compose.yml)
# Change: '--storage.tsdb.retention.time=30d' to '7d'
docker-compose up -d prometheus
```

### Advanced Configuration

**Enable Prometheus remote write:**
Edit `docker-compose.yml` to add remote storage configuration.

**Add alerting rules:**
1. Create `prometheus-rules.yml`
2. Mount it in `docker-compose.yml`
3. Reference in `prometheus.yml` under `rule_files:`

**Customize Loki retention:**
Create custom Loki config and mount it in `docker-compose.yml`.

**Enable Grafana SMTP:**
Add environment variables to Grafana service in `docker-compose.yml`.
